## Рентген (rentgen.py) — проверка железа компьютера (Windows и Linux)

Программа на Python «просвечивает» компьютер: собирает подробную информацию обо
всём железе, подсказывает, не б/у ли оно, и по желанию проверяет процессор
нагрузочным тестом. Отчёт сохраняется в трёх форматах: **TXT** (то же, что в
консоли), **HTML** (удобно читать в браузере) и **JSON** (для обработки другими
программами).

Сторонние библиотеки не нужны, программа только читает сведения и ничего не
меняет в системе.

* **В Windows** данные берутся из WMI/CIM через встроенный PowerShell, из реестра
  и напрямую у драйверов (батарея, журнал SMART NVMe-дисков).
* **В Linux** — напрямую из ядра (`/sys`, `/proc`), таблиц прошивки SMBIOS
  (модули памяти, серийные номера) и у NVMe-контроллера (журнал SMART).
  Если в системе есть `smartctl` или `nvidia-smi`, программа возьмёт у них
  дополнительные данные, но и без них обходится.

### Проверка при покупке: не б/у ли железо

Сразу после сводки идёт раздел **«Проверка состояния»** с понятным итогом
(✔ — в порядке, ⚠ — обратите внимание, ✖ — неисправность):

| Что проверяется | Чего ждать от нового компьютера |
|---|---|
| Батарея | износ 0–5 %, почти нет циклов заряда |
| Накопители | наработка — единицы или десятки часов, записано немного, никаких ошибок SMART, переназначенных и нестабильных секторов |
| Оперативная память | модули работают на паспортной частоте; один модуль при свободном слоте — медленный одноканальный режим |
| Устройства | нет неисправных устройств |
| Даты изготовления | экрана (из EDID), модулей памяти (из SPD, в Linux) и батареи — по самой поздней видно, когда компьютер собран не раньше |
| Охлаждение процессора | под нагрузкой (параметр `--stress`) частота держится, процессор не сбрасывает её из-за перегрева |

Если ноутбук продают **без Windows** (с FreeDOS, с Linux или вообще без системы)
или не хочется трогать установленную систему, загрузитесь с флешки с Ubuntu —
см. «Запуск с загрузочной флешки» ниже.

### Что попадает в отчёт

| Раздел | Что показывается |
|---|---|
| Сводка | Главное о компьютере на одном экране |
| Проверка состояния | Итог: износ батареи, наработка и ошибки дисков, память, устройства |
| Компьютер | Производитель, модель, тип корпуса, серийный номер, UUID, признаки виртуальной машины |
| Операционная система | Версия и выпуск Windows (например, 23H2) или дистрибутив и ядро Linux, время работы |
| BIOS / UEFI | Производитель, версия, дата, режим загрузки (UEFI/Legacy), Secure Boot, версия SMBIOS |
| Материнская плата | Производитель, модель, ревизия, серийный номер |
| Процессор | Модель, **поколение и год выхода модели**, ядра/потоки, базовая и турбо-частота, кэш L2/L3, сокет, виртуализация |
| Нагрузочный тест (с `--stress`) | Температура, частота, потребление процессора, сброс частоты из-за перегрева, вентиляторы — в начале и в конце теста и по ходу |
| Оперативная память | Общий объём, тип (DDR4/DDR5…), скорость, слоты; каждый модуль: объём, частота, напряжение, производитель, партномер, серийный номер, **дата изготовления** (Linux) |
| Видеокарты | Модель, **архитектура и год выхода модели**, объём видеопамяти, предел мощности (TGP) у NVIDIA, драйвер, версия BIOS видеокарты, текущий режим, VEN:DEV |
| Мониторы | Модель (у ноутбука — модель матрицы встроенного экрана), производитель, диагональ, родное разрешение и частота, тип подключения (HDMI/DP…), дата выпуска |
| Накопители | Модель, SSD/HDD, NVMe/SATA/USB, объём, прошивка, состояние, температура, износ, **наработка, объём записанного**, ошибки SMART; разделы и тома |
| Сетевые адаптеры | Ethernet/Wi-Fi, MAC, скорость, IP-адреса, шлюз, DNS, драйвер |
| Звук, устройства ввода, камеры, Bluetooth, USB | Устройства, производители, VID:PID, драйверы, аудиокодеки (Linux) |
| Батарея | Заряд, паспортная и текущая ёмкость, **износ**, число циклов, дата изготовления (если батарея её сообщает) |
| Принтеры, оптические приводы, TPM | Основные сведения |
| Устройства с неполадками | Всё, что в Диспетчере устройств с ошибкой или без драйвера, с подсказкой, **что это за устройство** и нужен ли ему драйвер (например, служебные Bluetooth-каналы наушников вроде Airoha_APP, OTA1, xiaoai) |
| Все устройства | Полный список устройств по классам с драйверами |

### Даты и серийные номера: что можно узнать

* **Дата изготовления экземпляра** хранится не везде: в экране (EDID), в модулях
  памяти (микросхема SPD) и иногда в батарее. Процессоры, видеокарты и диски её
  не хранят — для них программа показывает **год выхода модели** (поколение).
* **Даты модулей памяти** читаются только в Linux: в Windows доступ к SPD есть
  лишь через сторонний драйвер (так делают CPU-Z и HWiNFO). Если в Linux даты не
  появились, загрузите драйвер SPD: `sudo modprobe ee1004` (DDR4) или
  `sudo modprobe spd5118` (DDR5) и запустите программу снова.
* **Серийные номера** есть у компьютера, материнской платы, модулей памяти,
  дисков, иногда у монитора и батареи. У потребительских процессоров и видеокарт
  серийного номера нет.
* **ID оборудования (VEN:DEV)** — это не серийный номер, а код модели:
  VEN — производитель чипа (10DE — NVIDIA, 1002 — AMD, 8086 — Intel), DEV — модель
  чипа. У всех одинаковых устройств он одинаковый; по нему удобно искать драйверы.

### Нагрузочный тест процессора

С параметром `--stress` программа после сбора сведений минуту нагружает все
потоки процессора вычислениями и раз в секунду снимает показания: частоту,
температуру, потребление и сброс частоты из-за перегрева. По ходу теста
промежуточные значения видны в окне, итог — в «Проверке состояния» и в разделе
«Нагрузочный тест процессора». Длительность можно задать: `--stress 300` —
пять минут.

* **В Linux** видно всё: температура и предел процессора (TjMax), частоты P- и
  E-ядер, потребление в ваттах, сколько секунд процессор сбрасывал частоту из-за
  перегрева, обороты вентиляторов (если ноутбук их сообщает).
* **В Windows** без сторонних драйверов видны частота и срабатывание защиты от
  перегрева, а температуру процессора Windows обычно не показывает. Нагрев точнее
  проверять в Linux с загрузочной флешки.
* Подключите зарядку — от батареи процессор работает медленнее. Поставьте
  ноутбук на стол и не закрывайте вентиляционные решётки.
* Мощные ноутбуки под полной нагрузкой греются до 90–100 °C, и это обычно
  штатно. Плохо, если процессор надолго упирается в температурный предел и
  частота сильно падает: так проявляются засохшая термопаста, пыль или
  неисправный вентилятор.
* Видеокарта не нагружается. Тест можно прервать клавишами Ctrl+C — отчёт всё
  равно сохранится с тем, что успели намерить.

### Видеокарта NVIDIA в Linux

В Live-режиме Ubuntu фирменного драйвера NVIDIA нет. Модель видеокарты программа
всё равно определит точно — по коду устройства VEN:DEV: у ноутбука с RTX 5080
будет видно, что это именно RTX 5080, а не 5070 Ti. Объём видеопамяти покажет
открытый драйвер nouveau, если он поддерживает эту видеокарту.

Предел мощности (TGP) и версию BIOS видеокарты сообщает только драйвер NVIDIA:
загрузитесь в Windows или положите на флешку Ventoy ещё и Pop!_OS в варианте
NVIDIA (<https://system76.com/pop/download>, для видеокарт GTX 16xx и новее) —
там драйвер уже есть, и программа возьмёт данные у `nvidia-smi`. Pop!_OS требует
выключить Secure Boot в BIOS. Перед загрузкой Windows **обязательно включите его
обратно**, иначе Windows с шифрованием диска (BitLocker) может попросить ключ
восстановления.

### Требования

* Windows 10 или 11, либо любой современный Linux (Ubuntu, Mint, Fedora, Debian…);
* Python 3.8 или новее. В Linux он почти всегда уже установлен, для Windows —
  <https://www.python.org/downloads/> (при установке отметьте «Add python.exe to PATH»).

### Запуск в Windows

**Проще всего:** дважды щёлкните `rentgen.bat`. Отчёт появится в окне,
файлы сохранятся рядом с программой, а HTML-версия откроется в браузере.

С нагрузочным тестом: откройте папку с программой, в адресной строке Проводника
наберите `cmd`, нажмите Enter и в открывшемся окне выполните

```bat
rentgen.bat --stress
```

Из командной строки можно запускать и саму программу:

```bat
python rentgen.py
python rentgen.py --elevate --stress
```

Для **полного** отчёта (TPM, наработка и износ дисков, подробности батареи)
нужны права администратора — параметр `--elevate` попросит их сам.

### Запуск в Linux

```sh
sh rentgen.sh
sh rentgen.sh --stress
```

или то же самое вручную:

```sh
python3 rentgen.py --elevate --open --stress
```

Для полного отчёта (модули памяти, серийные номера, SMART дисков, потребление
процессора в тесте) нужны права root: с параметром `--elevate` программа спросит
пароль через `sudo`, а отчёт сохранит и откроет от имени обычного пользователя.
Можно запускать и просто `sudo python3 rentgen.py`.

SMART NVMe-дисков программа читает сама. Для SATA- и USB-дисков установите
smartmontools: `sudo apt install smartmontools`.

### Запуск с загрузочной флешки

Так можно проверить любой компьютер — с FreeDOS, без системы или с Windows,
которую не хочется трогать. Ничего на компьютер не устанавливается.

1. Скачайте Ubuntu LTS (<https://ubuntu.com/download/desktop>, ISO-файл около
   6,5 ГБ, нужна флешка от 16 ГБ) и сделайте флешку программой Ventoy
   **версии 1.1.18 или новее** (<https://github.com/ventoy/Ventoy/releases>):
   в Ventoy2Disk.exe выберите флешку, оставьте включённым «Option → Secure Boot
   Support» и нажмите «Install». Затем просто скопируйте на флешку ISO-файл,
   а рядом положите `rentgen.py`, `rentgen.sh` и папку `ventoy` (в ней
   настройка Ventoy, без которой Ubuntu 26.04 иногда не загружается).
2. Загрузите компьютер с флешки (меню загрузки обычно открывается клавишей
   F12, F11, F8 или Esc при включении), в меню Ventoy выберите ISO Ubuntu,
   а в установщике — «Попробовать Ubuntu».

   Если включён Secure Boot, при первой загрузке на этом компьютере появится
   синий экран: OK → «Enroll key from disk» → VTOYEFI →
   `ENROLL_THIS_KEY_IN_MOKMANAGER.cer` → Continue → Yes → Reboot, и снова
   загрузитесь с флешки.
3. Подключите зарядку. Откройте файловый менеджер, зайдите на флешку (диск
   «Ventoy»), щёлкните правой кнопкой по пустому месту → «Открыть в терминале»
   и выполните:

   ```sh
   sh rentgen.sh --stress
   ```

   Без `--stress` будет только отчёт, без нагрузочного теста. Если пункта
   «Открыть в терминале» нет, откройте терминал (Ctrl+Alt+T), наберите
   `sh ` с пробелом, перетащите в окно терминала файл `rentgen.sh`, допишите
   ` --stress` и нажмите Enter.

Отчёт сохранится прямо на флешку и откроется в браузере. В Live-режиме
пароль для `sudo` не нужен. В Ventoy старше 1.1.18 флешка внутри Ubuntu
«занята» и не открывается — обновите Ventoy (кнопка «Update» в
Ventoy2Disk.exe, файлы на флешке сохраняются).

**Если флешка не загружается** (ISO-файл распаковывать не нужно — Ventoy
загружает его как есть):

* Компьютер не видит флешку в меню загрузки или сразу загружает Windows —
  скорее всего, на флешку не установлен сам Ventoy, а ISO просто скопирован.
  Запустите Ventoy2Disk.exe: справа в строке «Ventoy In Device» должна быть
  версия. Если там пусто, нажмите «Install» (флешка очистится) и скопируйте
  файлы заново.
* Синий экран «Verification failed: (0x1A) Security Violation» — не ошибка,
  а первая загрузка с Secure Boot, см. шаг 2.
* Меню Ventoy появляется, но Ubuntu 26.04 зависает на крутящемся кружке или
  чёрном экране — это известная проблема Ubuntu 26.04 с Ventoy. Проверьте дату
  и время в BIOS и скопируйте в корень флешки папку `ventoy` из этого
  репозитория (в ней настройка `VTOY_LINUX_REMOUNT`, которая помогает). Если
  не помогло — возьмите Ubuntu 24.04 LTS: у неё такой проблемы с Ventoy нет.
* Ventoy сообщает об ошибке в самом ISO-файле — он скачался не полностью,
  скачайте заново.

**Без Ventoy** флешку можно записать программой Rufus (<https://rufus.ie>,
режим «ISO-образ»): она загружается и с Secure Boot без синего экрана.
Скопируйте на неё программу из Windows, а в Ubuntu запустите
`sh /cdrom/rentgen.sh --stress`. Флешка в этом случае доступна только для
чтения, поэтому отчёт попадёт в папку «Документы» — она в оперативной памяти
и после перезагрузки пропадёт, так что смотрите отчёт сразу или скопируйте
его на другую флешку.

### Параметры

| Параметр | Назначение |
|---|---|
| `-o ПАПКА`, `--output ПАПКА` | Куда сохранять отчёты (по умолчанию — текущая папка) |
| `-f txt html json` | Какие форматы сохранять (по умолчанию все три) |
| `--open` | Открыть HTML-отчёт после создания |
| `--elevate` | Получить права администратора (в Linux — root через sudo) |
| `--stress [СЕК]` | После сбора сведений провести нагрузочный тест процессора (по умолчанию 60 секунд, можно от 10 до 3600) |
| `--anon` | Скрыть серийные номера, UUID, MAC и IP-адреса (в том числе MAC Bluetooth-устройств внутри ИД оборудования), имена компьютера и пользователя — удобно, чтобы выложить отчёт на форум |
| `--no-devices` | Не включать полный список устройств |
| `--no-save` | Только вывести отчёт в консоль, без файлов |
| `-q`, `--quiet` | Не выводить отчёт в консоль, только сохранить файлы |
| `--pause` | Ждать нажатия Enter перед закрытием окна |
| `--dump-raw` | Дополнительно сохранить «сырые» данные (для отладки) |
| `--load-raw ФАЙЛ` | Построить отчёт из ранее сохранённых сырых данных (на любой системе) |

### Как собрать в один .exe (по желанию)

```bat
pip install pyinstaller
pyinstaller --onefile --name rentgen rentgen.py
```

Готовый `dist\rentgen.exe` запускается на любом компьютере с Windows,
даже без установленного Python.
